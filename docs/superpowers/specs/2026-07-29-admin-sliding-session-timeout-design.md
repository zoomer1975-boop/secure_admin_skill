# 관리자 슬라이딩 세션 타임아웃 설계

## 목적

`building-secure-admin-pages` Skill에 관리자 무활동 세션 정책을 추가한다. 개인정보취급자가 일정 시간 업무처리를 하지 않으면 접속을 실제로 차단하도록 한 「개인정보의 안전성 확보조치 기준」 제6조제4항을 구체화하되, 최초 로그인 이후의 누적시간이나 별도의 30분 상한은 두지 않는다.

## 선택한 방식

하나의 10분 슬라이딩 무활동 타이머를 사용한다.

- 서버가 확인한 마지막 관리자 업무 활동 시점부터 10분 동안 세션을 유지한다.
- 유효한 업무 활동이 발생할 때마다 만료시각을 `현재 시각 + 10분`으로 교체한다. 기존 만료시각에 시간을 더하지 않으므로 시간이 누적되지 않는다.
- 최초 로그인 시점부터 계산하는 절대 세션 상한과 별도의 30분 타이머는 두지 않는다.
- 사용자 의도로 발생하고 인증·인가된 관리자 조회, 생성, 수정, 삭제, 다운로드, 내보내기 요청만 활동으로 인정한다.
- 자동 새로고침, 백그라운드 폴링, heartbeat, 클라이언트의 마우스·키보드 이벤트는 활동으로 인정하지 않는다.

10분 슬라이딩 타이머만으로 무활동 차단과 활동 중 연장을 모두 충족한다. 10분 무활동 타이머와 30분 연장 타이머를 함께 두면 두 만료 규칙의 우선순위가 불명확하고, 10분 무활동 차단을 강화하지도 않으므로 추가하지 않는다.

## 차단 및 재접속

- 10분 동안 유효한 업무 활동이 없으면 서버에서 세션을 무효화하여 이후 정보 송수신을 차단한다.
- 화면보호기, 화면 잠금, 로그인 화면 표시만으로 접속 차단을 대신하지 않는다.
- 만료된 세션은 자동 갱신하거나 자동 로그인하지 않는다.
- 재접속 시 최초 로그인과 동일한 비밀번호 및 TOTP 인증 절차를 다시 요구한다.
- 세션 만료에 따른 자동 로그아웃을 기존 감사 로그 계약에 따라 기록하며 세션 토큰은 기록하지 않는다.

## 내부 관리계획

Skill은 구현 대상 시스템이 10분 무활동 제한, 활동 인정 범위, 서버 측 차단 방식, 재인증 절차를 내부 관리계획에 명시하도록 요구한다. 장시간 세션 예외 기능은 추가하지 않는다. 업무상 예외가 실제로 필요해질 때 별도 승인, 사유·기간 기록, 종료 후 원상 복구 요건을 설계한다.

기존 주소, 계정·인증, IP 허용목록, 권한, 관리자 관리, 감사 로그, 개인정보 보유·파기 및 실패 처리 계약은 모두 그대로 유지한다.

## 변경 범위

- `skills/building-secure-admin-pages/SKILL.md`: `Accounts and authentication`에 슬라이딩 무활동 세션 계약을 추가한다.
- `test/install.test.mjs`: 설치된 Skill에 10분 무활동, 활동 시 비누적 갱신, 서버 측 차단, 자동 요청 제외 및 재인증 문구가 모두 포함되는지 검증한다.
- README, 설치 프로그램 및 패키지 구조는 변경하지 않는다.

## 검증

- 테스트를 먼저 추가하고 새 계약 문구가 없어서 실패하는지 확인한다.
- 최소한의 Skill 문구를 추가한 뒤 `npm test`가 통과하는지 확인한다.
- `npm pack --dry-run`으로 배포 패키지에 수정된 Skill이 포함되는지 확인한다.

## 검토한 대안

1. **10분 슬라이딩 무활동 타이머**: 선택안. 요구사항과 개인정보보호 지침을 가장 직접적으로 표현한다.
2. **10분 무활동 타이머와 최초 로그인 기준 30분 절대 상한**: 활동 시 계속 연장해야 한다는 요구와 충돌하여 제외한다.
3. **30분 슬라이딩 타이머**: 10분 무활동 시 로그아웃 요구와 충돌하여 제외한다.
