# 관리자 중복 로그인 차단 설계

## 목적

`building-secure-admin-pages` Skill에 관리자 계정의 동시 접속(중복 로그인) 정책을 추가한다. 현재 Skill은 1인 1계정과 세션 폐기 시점만 규정할 뿐, 한 계정으로 여러 곳에서 동시에 로그인할 수 있는지에 대한 계약이 없다. 계정 공유와 세션 탈취를 실제로 탐지·차단하려면 동시 세션 수를 서버에서 제한해야 한다.

## 선택한 방식

계정당 활성 세션을 하나만 허용하고, 최신 로그인을 우선한다.

- 인증에 성공한 계정에 이미 활성 세션이 있으면, 새 세션을 발급하기 전에 서버에서 기존 세션을 무효화한다.
- 무효화된 세션의 이후 요청은 모두 차단한다.
- 중복 판정 기준은 불변 내부 계정 식별자다. 브라우저, 기기, IP 주소로 판정하지 않는다. 그래야 다른 브라우저·기기·회선에서 병렬 세션을 유지할 수 없다.
- 종료된 세션에는 "다른 곳에서 로그인되었다"는 사실만 알린다. 다른 세션의 IP, 기기, 위치는 노출하지 않는다.
- 중복 로그인과 그로 인한 강제 로그아웃을 각각 감사 로그에 남기되 세션 토큰은 기록하지 않는다.
- 1계정 1세션 제한을 내부 관리계획에 명시하도록 요구한다.

## 검토한 대안

1. **최신 로그인 우선, 기존 세션 강제 종료**: 선택안. 정당한 관리자가 기기를 바꾸거나 세션이 비정상 종료된 경우에도 스스로 복귀할 수 있고, 계정 공유·세션 탈취는 강제 로그아웃과 감사 기록으로 즉시 드러난다.
2. **기존 세션 우선, 신규 로그인 거부**: 공격자가 먼저 로그인해 두면 정당한 관리자가 잠기고, 비정상 종료된 세션이 무활동 만료될 때까지 업무가 중단되므로 제외한다.
3. **계정당 N개 동시 세션 허용**: 1인 1계정 원칙과 계정 공유 탐지 목적을 약화시키므로 제외한다.
4. **기기·IP 단위 예외 허용**: 허용 IP 목록과 판정 기준이 뒤섞여 우회 경로가 생기므로 제외한다.

## 무활동 타임아웃과의 관계

`2026-07-29-admin-sliding-session-timeout-design.md`의 10분 슬라이딩 무활동 정책과 독립적이다. 무활동 만료는 "언제 세션이 끝나는가", 중복 로그인 차단은 "동시에 몇 개의 세션이 살아 있는가"를 정한다. 두 계약은 서로를 대체하지 않는다. 해당 슬라이딩 세션 계약은 아직 SKILL.md에 반영되지 않은 별도 작업이며, 이번 변경은 그 작업을 기다리지 않는다.

## 변경 범위

- `skills/building-secure-admin-pages/SKILL.md`: `Accounts and authentication`의 세션 폐기 항목 바로 뒤에 중복 로그인 계약을 추가한다.
- `test/install.test.mjs`: 설치된 Skill에 1계정 1세션, 기존 세션 무효화, 계정 식별자 기준 판정, 정보 비노출 안내, 감사 기록 및 내부 관리계획 문구가 모두 포함되는지 검증한다.
- README, 설치 프로그램, 패키지 구조, 기존 보안 계약은 변경하지 않는다.

## 검증

- 테스트를 먼저 추가하고 새 계약 문구가 없어서 실패하는지 확인한다.
- 최소한의 Skill 문구를 추가한 뒤 `npm test`가 통과하는지 확인한다.
- `npm pack --dry-run`으로 배포 패키지에 수정된 Skill이 포함되는지 확인한다.
